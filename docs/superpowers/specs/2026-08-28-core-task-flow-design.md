# 협업 도구 핵심 작업 흐름 설계

## 목적

Drive의 협업 도구 설계를 바탕으로, 이후 기능을 계속 확장할 수 있는 첫 번째 실행 가능한 웹 애플리케이션을 만든다. 첫 버전은 로그인 없이 고정 사용자 한 명을 사용하며, 작업 생성부터 실제 작업 시작까지의 핵심 흐름을 완성한다.

## 성공 기준

사용자는 다음 흐름을 브라우저에서 끝까지 수행할 수 있어야 한다.

1. 작업 초안을 만든다.
2. 필수 정보를 채워 작업 풀에 공개한다.
3. 작업 풀에서 작업을 가져간다.
4. 가져간 작업을 내 작업에서 확인한다.
5. 작업을 시작한다.
6. 새로고침하거나 앱을 다시 실행한 뒤에도 상태가 유지된다.

## 범위

### 포함

- 로그인 없는 고정 사용자 한 명
- 내 작업 화면
- 작업 풀 화면
- 새 작업 초안 작성 화면
- 작업 초안 공개
- 공개 작업 가져가기
- 가져간 작업 시작
- SQLite 영속 저장
- 주요 상태 변경 이력
- 한국어 입력 검증 및 오류 메시지
- 업무 규칙 단위 테스트
- 핵심 흐름 통합 및 브라우저 테스트

### 제외

- 로그인과 사용자 초대
- 복수 사용자 간 실시간 경쟁 처리 UI
- 권한 및 작업 스코프 관리 화면
- 일정 블록과 공용 연대표
- 결과물, 검토, 완료
- 대기, 보류, 의존성, Subtask, Handoff
- 알림, 파일 보관, 검색
- 운영 배포와 외부 스토리지

제외 항목을 나중에 추가할 수 있도록 상태 모델과 코드 경계는 원본 설계의 방향을 따른다.

## 기술 접근

Next.js 단일 애플리케이션으로 화면과 서버 명령을 함께 구성한다. SQLite를 로컬 데이터베이스로 사용한다. 데이터 접근 계층은 화면 및 업무 규칙과 분리하여, 나중에 PostgreSQL로 교체할 때 화면과 명령 인터페이스를 유지할 수 있게 한다.

화면은 데이터베이스를 직접 수정하지 않는다. 모든 변경은 의미가 분명한 서버 명령을 거친다.

- `createDraft`
- `publishTask`
- `takeTask`
- `startTask`

각 명령은 입력과 현재 상태를 검사하고, Task 갱신과 TaskEvent 기록을 하나의 트랜잭션으로 저장한다.

## 구성 요소

### 화면

- `내 작업`: 고정 사용자가 가져간 작업을 상태별로 표시한다.
- `작업 풀`: 공개되었고 담당자가 없는 작업을 표시한다.
- `새 작업 만들기`: 초안을 생성하고 필수 정보를 입력해 공개한다.
- `작업 상세`: 상태와 주요 정보를 보여주고 가능한 다음 행동을 제공한다.

기존 와이어프레임의 어두운 좌측 탐색, 밝은 작업 영역, 행 형태 작업 카드, 상태색과 우선순위 표현을 재사용한다. 첫 버전에 없는 메뉴는 비활성 상태로 노출하거나 숨긴다.

### 서버 명령 계층

업무 행동별 입력 검증, 상태 전이, 동시성 검사를 담당한다. 화면은 명령 결과만 받아 갱신한다.

### 도메인 규칙 계층

공개 가능 조건과 상태 전이 가능 여부를 순수 함수 중심으로 표현한다. 저장 방식과 독립적으로 테스트할 수 있어야 한다.

### 데이터 접근 계층

SQLite 조회, 트랜잭션, 초기 샘플 데이터 생성을 담당한다. 상위 계층은 SQLite 고유 문법에 직접 의존하지 않는다.

## 데이터 모델

### User

- `id`
- `name`
- `createdAt`

첫 버전 시작 시 고정 사용자 한 명을 생성한다.

### WorkType

- `id`
- `name`
- `color`
- `isActive`

초기값으로 기획, 개발, QA를 제공한다.

### Task

- `id`
- `title`
- `goal`
- `workTypeId`
- `estimatedBlocks`
- `deadline`
- `publicationState`: `draft | published`
- `workStatus`: `open | taken | in_progress`
- `assigneeId`
- `version`
- `createdAt`
- `updatedAt`

초안은 `publicationState=draft`, `workStatus=open`, `assigneeId=null`로 생성한다. 공개와 실행 상태를 한 enum에 섞지 않는다.

### TaskEvent

- `id`
- `taskId`
- `eventType`: `created | published | taken | started`
- `actorId`
- `fromState`
- `toState`
- `createdAt`

이력은 사용자 화면 복원과 향후 활동 피드 확장을 위한 최소 정보만 기록한다.

## 업무 규칙

### 초안 생성

- 제목 없이 임시 초안을 만들 수 있다.
- 생성자는 고정 사용자다.

### 공개

- 현재 공개 상태가 `draft`여야 한다.
- 제목, 목표, 작업 종류, 예상 작업량이 필요하다.
- 작업 종류는 활성 상태여야 한다.
- 예상 작업량은 양의 정수 블록이어야 한다.
- 성공 시 `publicationState=published`로 변경하고 `published` 이벤트를 기록한다.

### 가져가기

- 공개 상태가 `published`여야 한다.
- 실행 상태가 `open`이어야 한다.
- 담당자가 없어야 한다.
- 성공 시 `assigneeId`를 고정 사용자로 설정하고 `workStatus=taken`으로 변경한다.

### 시작

- 현재 사용자가 담당자여야 한다.
- 실행 상태가 `taken`이어야 한다.
- 성공 시 `workStatus=in_progress`로 변경한다.

### 동시성

Task의 `version`을 모든 변경 명령에서 비교한다. 오래된 화면에서 보낸 명령은 충돌로 거부하고 최신 상태를 다시 불러오도록 안내한다. SQLite 트랜잭션 안에서 상태 확인, 변경, 이벤트 기록을 처리한다.

## 데이터 흐름

1. 서버가 SQLite에서 화면용 데이터를 읽는다.
2. 사용자가 작업 버튼을 누르면 해당 서버 명령을 호출한다.
3. 명령이 입력, 현재 상태, 버전을 검증한다.
4. 트랜잭션에서 Task와 TaskEvent를 함께 저장한다.
5. 성공 후 관련 화면 데이터를 다시 읽어 표시한다.

## 오류 처리

오류는 내부 예외를 그대로 노출하지 않고 분류된 결과로 반환한다.

- 입력 오류: 해당 입력란 근처에 한국어 메시지를 표시한다.
- 잘못된 상태 전이: 화면 상단에 현재 상태에서 할 수 없는 행동임을 표시한다.
- 버전 충돌: 다른 변경이 있었음을 알리고 최신 데이터를 다시 불러온다.
- 저장 실패: 작업이 반영되지 않았음을 명확히 알리고 재시도를 제공한다.

성공하지 않은 명령에서는 TaskEvent를 남기지 않는다.

## 테스트

### 단위 테스트

- 공개 필수값 검증
- 공개 상태 전이
- 가져가기 자격과 상태 검사
- 시작 담당자와 상태 검사
- 잘못된 상태 전이 거부

### 통합 테스트

- 명령 성공 시 Task와 TaskEvent가 함께 저장되는지 확인
- 실패 시 두 테이블 모두 변경되지 않는지 확인
- 같은 버전으로 동시에 가져가기를 시도할 때 한 요청만 성공하는지 확인

### 브라우저 테스트

- 초안 생성부터 시작까지 전체 흐름
- 작업 풀에서 내 작업으로 이동하는 화면 변화
- 새로고침 후 상태 유지
- 필수값 누락과 충돌 오류 표시

## 초기 데이터

고정 사용자, 작업 종류 세 개, 공개 작업 몇 개를 개발 초기 데이터로 제공한다. 초기화는 반복 실행해도 중복 데이터를 만들지 않아야 한다.

## 향후 확장 경계

- 고정 사용자 조회를 세션 사용자 조회로 교체한다.
- SQLite 데이터 접근 구현을 PostgreSQL 구현으로 교체한다.
- 도메인 명령에 권한과 MemberWorkScope 검사를 추가한다.
- 기존 Task 상태 모델에 waiting, on_hold, review_requested 등을 확장한다.
- TaskEvent를 알림과 활동 피드의 입력으로 재사용한다.

첫 버전에서는 이 확장을 미리 구현하지 않는다.
